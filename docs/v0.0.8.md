# oneGrid v0.0.8 — Implementation Patterns Report

This report documents the implementation patterns the oneGrid v0.0.8
milestone converged on. Twelve cross-cutting concerns landed in
critical-path order — protocol decisions first, then five real
database adapters that prove the protocol portable, finally a
schema-introspection helper that ties everything together.

Like v0.0.7, this is post-hoc: each section ends with a
`Code surface in oneGrid` block pointing at the actual paths shipped
on `main` and the test gates wired in CI today. References cite
public W3C / RFC / vendor documentation only — no commercial source,
no incumbent-grid prose.

---

## 1. Canonical keyset cursor codec

**Architecture.** Replace the v0.0.5–v0.0.7 `offset:N` cursor (used by `SsrmRowSource`'s synchronous random-access bridge) with a canonical keyset shape: `ks:<base64-of-utf8-of-json({s: sortValues, r: rowId}))>`. The `ks:` prefix is a version sentinel — future cursor formats can ship behind a different prefix without breaking existing clients (they'll throw on decode). Legacy `offset:N` is still parsable via `parseLegacyOffsetCursor` during the migration window.

The decoder tolerates two payload shapes — short (`{s, r}`) AND long (`{sortValues, rowId}`) — so cursors emitted by the Drizzle / Kysely adapters before this canonicalization round-trip cleanly. The encoder always produces the short shape going forward.

The protocol stays types-only per the architectural guardrail: the codec lives in `@onegrid/ssrm`, and the database adapters (which depend only on `@onegrid/protocol`) ship self-contained copies that produce the same `ks:` wire format.

**Edge cases**
- `SsrmRowSource` does random access over row indices; keyset cursors are forward-only. The bridge keeps using offset cursors internally; the protocol mock server accepts both formats. Real database adapters reject offset cursors silently (treat as "first block") because OFFSET is O(N) on large tables.
- `rowId` must be `string | number`. ObjectId, UUID, BigInt are coerced to string at the edge; the codec rejects unsupported shapes.
- Sort values include `null` for `nulls: 'first' | 'last'` semantics; `compareKeysetCursors` follows the SortField's `nulls` field.

**Code surface in oneGrid**
`packages/ssrm/src/cursor.ts` (canonical codec + helpers), `packages/protocol/src/index.ts` (Cursor / KeysetCursor docstrings), `packages/adapters/{drizzle,kysely}/src/cursor.ts` (self-contained copies aligned to the same wire format), `apps/ssrm-mock-server/src/server.ts` (resolveStartOffset accepts both formats).

**Test strategy**
24 unit tests in `packages/ssrm/src/__tests__/cursor.test.ts` covering round-trip, null sort values, long-form payload acceptance, malformed payload errors, legacy offset detection, `cursorFromRow` shape mirroring SortModel, and `compareKeysetCursors` with desc/nulls/tiebreaker semantics.

**References:** OData v4.01 cursor / `$skiptoken` semantics — https://docs.oasis-open.org/odata/odata/v4.01/odata-v4.01-part1-protocol.html · Postgres recursive CTEs — https://www.postgresql.org/docs/current/queries-with.html

## 2. Aggregation-pushdown protocol

**Architecture.** `BlockRequest.aggregations?: AggregationModel` extends the existing `grouping` field. When set, servers compute `GROUP BY` + per-group rollups themselves and emit one row per distinct group key with the alias columns (default `${fn}_${columnId}`) plus a synthetic `__count__` carrying per-group row count for the chevron+badge.

For a 1M-row dataset grouped by `status`, the wire payload collapses from 1M raw rows to 5 group-summary rows. That's the protocol payoff.

`AggregationModel` already existed (carrying sum/avg/count/countDistinct/min/max/first/last) — adding it to `BlockRequest` was a one-line type extension. The five database adapters all support sum/avg/count/countDistinct/min/max in their compilers; `first`/`last` throw because they're non-trivial in standard SQL (would need a window function plus `LIMIT 1`).

**Edge cases**
- Cache invalidation: aggregations participate in the cache fingerprint. Changing a measure (`sum` → `avg`) or alias invalidates the cached blocks rather than serving stale rollups under the new spec.
- Multi-level grouping with `openKeys` is a v0.0.9 follow-up — currently we emit one row per top-level group child only. The protocol shape supports it; the adapter compilers + mock server don't yet.
- Per-adapter aggregator dialect:
  - Postgres: `COALESCE(SUM, 0)::float` (sum returns NULL on empty groups; cast pins type)
  - MySQL: `CAST(COALESCE(SUM, 0) AS DOUBLE)`
  - SQLite: `COALESCE(SUM, 0)` (dynamic typing)
  - ClickHouse: `toFloat64(sum(...))` (sum returns 0 natively, no COALESCE needed)
  - Mongo: `{ $sum: '$amount' }` inside a `$group` stage

**Code surface in oneGrid**
`packages/protocol/src/index.ts` (BlockRequest.aggregations), `packages/ssrm/src/{fingerprint,cache}.ts` (cache key includes aggregations), `apps/ssrm-mock-server/src/server.ts` (`fetchGroupedBlock` uses `@onegrid/data`'s `groupRows` with the request's aggregations + rowFilter).

**Test strategy**
3 Playwright gates in `apps/benchmarks/src/agg-pushdown.spec.ts` against the real mock server (5 rollup rows totaling 1M; group-without-agg returns count-only rows; aggregations scoped to active filter). 5 fingerprint cases (agg vs no-agg, sum vs avg, alias differences, ordering, all distinct).

**References:** Postgres GROUP BY — https://www.postgresql.org/docs/current/queries-table-expressions.html#QUERIES-GROUP · OData aggregation extension `$apply` — https://docs.oasis-open.org/odata/odata-data-aggregation-ext/v4.0/cs01/odata-data-aggregation-ext-v4.0-cs01.html

## 3. Real-time row diff protocol

**Architecture.** Single versioned envelope: `RowDiff { kind: 'insert' | 'update' | 'delete', version: number, pkey: string | number, fields?: Record<string, unknown> }`. Versions are monotonically increasing per source. Servers wrap every CDC event in this shape regardless of upstream (Postgres LISTEN/NOTIFY, Mongo change streams, Kafka, Debezium); clients track last-seen version and request a resync when the next emit's version isn't `lastSeenVersion + 1`.

`ResyncRequest { fromVersion }` and `ResyncResponse { fromVersion, toVersion, diffs: RowDiff[], snapshot?: true }` cover the two recovery cases. When the gap is small enough to replay incrementally, the server returns the missing diffs. When the gap is too large to keep history for, the server signals `snapshot: true` and the client wipes its cache.

Payload is deliberately flat — no nested `patch` envelope — because high-throughput change streams may emit thousands per second and per-event overhead matters.

**Edge cases**
- Duplicates: `RowDiffTracker` routes diffs with `version <= lastSeenVersion` to `onDuplicate` instead of treating them as new emits. Common cause is a server replaying after a network flap.
- No baseline: `initialVersion = -1` means "accept any starting version on the first diff received." Pass a known version when resuming a session.
- Pause semantics: while paused awaiting a resync, the tracker drops *all* live diffs (they'll be re-delivered as part of the resync response). Without this, an out-of-order mix of replayed + live diffs would fight for the version cursor.
- The tracker is pure state — never touches the wire. The transport / fetch is the consumer's concern; `createRowDiffStream` (v0.0.8 item 4) wires the two together.

**Code surface in oneGrid**
`packages/protocol/src/index.ts` (RowDiff / ResyncRequest / ResyncResponse), `packages/ssrm/src/row-diff-tracker.ts` (gap detection state machine).

**Test strategy**
9 unit tests covering contiguous streams, no-baseline / explicit baseline starting versions, gap detection + pause, resume advances high-water mark, snapshotTo rebases version + unblocks pause, duplicates routed to onDuplicate, batch processing pauses on first gap.

**References:** Debezium Kafka Connect change events — https://debezium.io/documentation/reference/stable/connectors/postgresql.html · Postgres LISTEN/NOTIFY — https://www.postgresql.org/docs/current/sql-notify.html · MongoDB change streams — https://www.mongodb.com/docs/manual/changeStreams/

## 4. Universal CDC adapter shape

**Architecture.** `CdcAdapter { subscribe, resync, close? }` is the in-process interface every source-specific adapter implements. The five adapters in v0.0.8 — Postgres LISTEN/NOTIFY, MySQL polling-outbox, SQLite (deferred to v0.0.9), ClickHouse (N/A — append-mostly), MongoDB change streams — all conform to the same shape. Consumers of the unified stream don't care which source produced the events.

`createRowDiffStream(adapter, options)` composes a CdcAdapter with a `RowDiffTracker`: live in-order diffs flow to `onDiff`; gaps trigger an automatic resync via `adapter.resync()`; incremental responses replay through `onDiff` and advance the tracker; snapshot responses signal the consumer to wipe their cache.

Replay-path detail: when the resync response lands with diffs to replay, `onDiff` is called *directly* for each replayed diff rather than re-routing through `tracker.accept()`. The tracker's paused-gate would drop replayed diffs otherwise. The tracker is re-armed via `resume(throughVersion)` with the post-replay high-water mark.

**Edge cases**
- Backpressure: `subscribers` is a Set, not a queue. If a subscriber is slow, the others still receive the diff. Adapters are responsible for not over-emitting (e.g. polling adapters bound `LIMIT pollLimit` per round).
- Reconnect handling: WebSocket-style adapters can call `stream.resyncNow()` after a transport reconnect to force a sync from the current `lastVersion()`.
- Resync error: if `adapter.resync()` rejects, the stream stays paused so the consumer's recovery policy can decide (retry, abandon, surface to user).

**Code surface in oneGrid**
`packages/ssrm/src/cdc.ts` (CdcAdapter interface + `createRowDiffStream`), `packages/adapters/postgres/src/cdc.ts` (LISTEN/NOTIFY adapter), `packages/adapters/mysql/src/cdc.ts` (polling-outbox adapter), `packages/adapters/mongo/src/cdc.ts` (change-streams adapter).

**Test strategy**
7 cases against a fake CdcAdapter (in-order diffs, gap → incremental resync, gap → snapshot resync, drops live diffs while paused, resync error keeps stream paused, `resyncNow()` forces manual resync, close() unsubscribes). Plus 11 cases in the Postgres CDC adapter, 7 in MySQL, 9 in Mongo.

**References:** Mongo change streams resume tokens — https://www.mongodb.com/docs/manual/changeStreams/#resume-tokens · Postgres LISTEN/NOTIFY — https://www.postgresql.org/docs/current/libpq-notify.html · Kafka Connect record schema — https://kafka.apache.org/documentation/#connect

## 5. Optimistic mutations + conflict resolution (real impl)

**Architecture.** `createOptimisticMutator({ dataSource, onApply, onCommit, onRollback, onTransportError })` orchestrates the optimistic-write lifecycle:

1. Caller invokes `apply(mutation)`.
2. The mutator immediately calls `onApply(mutation)` — UI feels instant.
3. The mutator submits the mutation via `dataSource.mutate([mutation])`.
4. Server returns a `MutationResultEntry`:
   - `MutationOk` → `onCommit(mutation, result)`. The server's authoritative `rowId` lets the consumer reconcile any local placeholder ids.
   - `MutationConflict` → `onRollback(mutation, result)` with `result.server` (server's truth).
   - `MutationError` → `onRollback(mutation, result)`.
5. Transport rejection → `onTransportError(mutation, err)` and the apply rejects.

Per-mutation `clientId` is auto-generated (`og-<n>`) when omitted. The mutator tracks pending mutations by clientId so consumers can layer their own write-after-write policy (queue-and-replay, last-write-wins, or domain-specific).

**Edge cases**
- Server returns no entry for the clientId: synthesize a `MutationError { code: 'INTERNAL', message: 'No result entry returned for clientId.' }` and call `onRollback`. Without this, the consumer's `onApply` would persist forever.
- Concurrent mutations on the same row: the mutator doesn't deduplicate — that's the consumer's policy. `pending()` exposes in-flight mutations so the consumer can implement their own.
- Concurrency vs row-diff streams: when the CDC stream emits a `RowDiff` for a row that has a pending mutation, the consumer's reconciliation policy decides which "wins". The mutator stays unopinionated.

**Code surface in oneGrid**
`packages/ssrm/src/optimistic.ts` (createOptimisticMutator).

**Test strategy**
8 cases: onApply ordering (apply BEFORE server call), MutationConflict → onRollback, MutationError → onRollback, missing entry → synthesized error, transport reject → onTransportError + propagated reject, pending count tracks in-flight, auto-generated clientId, throws on construction when DataSource lacks `mutate`.

**References:** AbortController for stale-result cancellation — https://developer.mozilla.org/en-US/docs/Web/API/AbortController · CRDT concurrency models (Yjs / Automerge) — https://crdt.tech/

## 6. Arrow IPC ingestion

**Architecture.** `ArrowDecoder = (bytes: Uint8Array) => ReadonlyArray<Record<string, unknown>>` is a pluggable hook on `SsrmRowSourceOptions` and `SsrmTreeSourceOptions`. When the server emits a `BlockResponse<'arrow-ipc'>`, the row source delegates to the decoder; JSON-only deployments leave it omitted and never pay the cost.

The HTTP transport sniffs response `Content-Type`. JSON parses to `BlockResponse<'json'>` as before; `application/vnd.apache.arrow.stream` (the canonical Arrow IPC MIME) reads `arrayBuffer()`, wraps in `Uint8Array`, returns `BlockResponse<'arrow-ipc'>`. Cursors and total-row-count are carried via response headers (`x-onegrid-next-cursor`, `-prev-cursor`, `-total-row-count`) since binary bodies have nowhere to attach protocol metadata.

The `apache-arrow` package is NOT bundled. Adapter authors who want Arrow plug in their own decoder via `tableFromIPC` — recipe in the docstring.

**Edge cases**
- Cursor over Arrow: Arrow responses currently emit `null` cursors at the adapter layer (would require apache-arrow to derive). Consumers needing keyset over Arrow either decode client-side or use the JSON path for the first request to get a cursor, then switch.
- The mock server still emits JSON; ClickHouse is the v0.0.8 adapter that proves the Arrow path end-to-end.

**Code surface in oneGrid**
`packages/ssrm/src/row-source.ts` (ArrowDecoder + `decodeRows` dispatch), `packages/ssrm/src/tree-source.ts` (same), `packages/ssrm/src/transports/http.ts` (Content-Type sniff + arrayBuffer path), `packages/adapters/clickhouse/src/datasource.ts` (Arrow-format request).

**Test strategy**
5 unit tests (JSON pass-through, arrow-ipc with decoder, arrow-ipc without decoder caches the failure, tree-source decodes hierarchical arrow, tree-source falls back gracefully).

**References:** Apache Arrow IPC format — https://arrow.apache.org/docs/format/IPC.html · Arrow Project canonical MIME types — https://arrow.apache.org/docs/format/Glossary.html

## 7. Raw Postgres adapter (`@onegrid/postgres`)

**Architecture.** Pure SQL compiler `compileBlockQuery(req, table, cursor) → { sql, params }` translates filters (every ComparisonOperator + logical AND/OR/NOT), sorts (multi-column with `NULLS FIRST | LAST`), keyset cursors (row-tuple comparison `(a, b, _id) > (vA, vB, vId)` — Postgres seeks this via covering index), and aggregations (`SUM` → `COALESCE(SUM, 0)::float` to pin types and handle empty groups).

Identifier whitelisting at compile time: every column id is matched against the descriptor's `columns` list; unknown names throw before SQL is built. LIKE-special character escaping on contains / startsWith / endsWith. Mixed-direction sorts (some ASC + some DESC) are coerced to "all DESC if any DESC" for the cursor predicate; full per-column direction is a v0.0.9 follow-up.

CDC adapter subscribes to a single NOTIFY channel (default `onegrid_row_diff`) on a dedicated `pg.Client` connection. Application's database trigger (DDL-side, owned by the schema deployer) writes to an `onegrid_outbox` table + emits NOTIFY in one transaction; the adapter parses each NOTIFY payload as `RowDiff` JSON. Resync reads from the outbox via a caller-supplied query.

**Edge cases**
- LISTEN is per-session — must use `pg.Client`, NOT `pg.Pool`. Documented.
- `NOTIFY` payload has an 8KB limit. Trigger emits the full row; consumers with wider tables should emit only key fields and let the adapter re-fetch on resync.
- Composite primary keys: the compiler assumes `primaryKey` is a single column id. v0.0.9 adds composite key support.

**Code surface in oneGrid**
`packages/adapters/postgres/src/{sql,datasource,cdc}.ts`. README documents the recommended outbox+trigger DDL.

**Test strategy**
35 unit tests: 22 for the compiler (filters, sorts, keyset, grouping, identifier quoting), 7 for the data source against a fake `pg`, 11 for the CDC adapter against a fake LISTEN client.

**References:** node-postgres — https://node-postgres.com · Postgres trigger functions — https://www.postgresql.org/docs/current/plpgsql-trigger.html · Postgres NOTIFY — https://www.postgresql.org/docs/current/sql-notify.html

## 8. MySQL adapter (`@onegrid/mysql`)

**Architecture.** Mirrors the Postgres compiler intentionally — anywhere the two diverge in shape is a contained MySQL idiom rather than a protocol leak. Documented divergences:

| Concern | Postgres | MySQL |
|---|---|---|
| Identifier quoting | `"col"` | `` `col` `` |
| Placeholders | `$N` | `?` |
| `NULLS FIRST/LAST` | native | emulated `IS NULL` ordering |
| Case sensitivity | sensitive default | requires `BINARY` wrap |
| Aggregate type pinning | `::int` / `::float` | `CAST(... AS SIGNED)` / `CAST(... AS DOUBLE)` |

Row-tuple comparison `(a, b) > (1, 2)` works the same since MySQL 5.7 — confirming the protocol shape is portable.

CDC: MySQL has no LISTEN/NOTIFY equivalent. The adapter polls an outbox table every `pollIntervalMs` (default 500 ms) for rows whose `version` exceeds the last seen value. Polling is higher latency than NOTIFY but requires zero special configuration. Production deployments needing sub-second latency plug in a binlog-based CDC source (Debezium / Canal / Maxwell) that emits the same `RowDiff` shape.

**Edge cases**
- `JSON` columns: mysql2 returns these as TEXT by default. The adapter's `toRowDiff` tolerates both stringified JSON and pre-parsed objects.
- Polling under sustained writes: `pollLimit` (default 1000) caps per-round work so the outbox query stays bounded.

**Code surface in oneGrid**
`packages/adapters/mysql/src/{sql,datasource,cdc}.ts`. README documents the four divergences in a side-by-side table + outbox-trigger DDL (MySQL DELIMITER syntax).

**Test strategy**
25 unit tests: 14 compiler, 4 data source, 7 CDC.

**References:** mysql2 — https://github.com/sidorares/node-mysql2 · MySQL row constructor `(a,b) > (1,2)` — https://dev.mysql.com/doc/refman/8.0/en/row-subqueries.html · MySQL trigger syntax — https://dev.mysql.com/doc/refman/8.0/en/trigger-syntax.html

## 9. SQLite adapter (`@onegrid/sqlite`)

**Architecture.** Diverges from Postgres at exactly two places (placeholders + agg type pinning). Targets every popular SQLite driver — better-sqlite3 / node:sqlite (Node 22+) / bun:sqlite / Cloudflare D1 / libsql/Turso — through one queryable interface that accepts both sync and async returns.

`bigint` primary keys (better-sqlite3 with `safeIntegers(true)`) are coerced to `Number` for the cursor codec. SQLite's LIKE is case-insensitive for ASCII by default; `LOWER()`-wrap is added when the consumer asks for case-insensitive comparison. Every LIKE clause gets `ESCAPE '\'` so the LIKE-special character escaping works.

CDC is not in this package. SQLite-backed grids are typically single-writer (embedded apps, edge workers); when CDC is needed, the polling-outbox pattern from `@onegrid/mysql` applies the same way.

**Edge cases**
- Sync vs async drivers: the queryable returns `T | Promise<T>`; the data source `await Promise.resolve()`-wraps either case. Cheap.
- D1's `.results` field: D1 returns `{ results: ... }`; consumer adapts in their queryable wrapper.

**Code surface in oneGrid**
`packages/adapters/sqlite/src/{sql,datasource}.ts`. README has adapter recipes for all five supported drivers.

**Test strategy**
16 unit tests: 9 compiler, 7 data source (sync + async queryable + bigint primary keys + cursor flow).

**References:** SQLite syntax reference — https://www.sqlite.org/lang.html · Cloudflare D1 — https://developers.cloudflare.com/d1/

## 10. ClickHouse adapter (`@onegrid/clickhouse`)

**Architecture.** ClickHouse uses native named-parameter syntax (`{p0:Type}`) with type hints; positional placeholders aren't supported by the HTTP / TCP protocol. The compiler emits one named placeholder per value; type hints flow from `ChTableDescriptor.columnTypes` when provided, else fall back to `String` (ClickHouse coerces String literals to most other types).

Aggregations use ClickHouse's idiomatic `toFloat64()` / `toUInt64()` / `uniqExact()` casts to pin types stable across empty groups. `ILIKE` is native (not emulated like in Postgres).

Two response formats: `JSONEachRow` (default) for casual use; `Arrow` for the high-throughput columnar path. Arrow responses return `BlockResponse<'arrow-ipc'>` with raw `Uint8Array`; the consumer's `SsrmRowSource.decodeArrowIpc` materializes via `apache-arrow`. Keyset cursors over Arrow currently emit `null` (would require server-side decode); JSON-flat cursors work as expected.

CDC isn't in this package. ClickHouse is append-mostly + ReplacingMergeTree for updates — real CDC means upstream Debezium → Kafka engine tables, not adapter-side row pubsub.

**Edge cases**
- `String` fallback type: works for most queries but produces wrong results when ClickHouse strictly typechecks a parameter (e.g. `WHERE id = {p0:String}` against a `UInt64` column). Always pass `columnTypes`.
- Arrow IPC bytes: the consumer's apache-arrow integration is the only place the schema is interpreted; the adapter is dumb byte transport beyond that.

**Code surface in oneGrid**
`packages/adapters/clickhouse/src/{sql,datasource}.ts`. README documents the named-parameter trade-off + the apache-arrow recipe + why CDC is upstream.

**Test strategy**
16 unit tests: 11 compiler (named-parameter shape, type-hint inference, ILIKE, aggregation casts, identifier quoting), 5 data source (JSONEachRow, Arrow path, format dispatch).

**References:** ClickHouse query parameters — https://clickhouse.com/docs/en/interfaces/http#cli-queries-with-parameters · ClickHouse Arrow format — https://clickhouse.com/docs/en/interfaces/formats#data-format-arrow · ClickHouse aggregate functions — https://clickhouse.com/docs/en/sql-reference/aggregate-functions

## 11. MongoDB adapter (`@onegrid/mongo`)

**Architecture.** Most divergent shape — Mongo uses query documents and aggregation pipelines instead of SQL strings. The compiler returns either:
- `CompiledFlatQuery { kind: 'find', filter, sort, projection, limit }` for non-grouped requests
- `CompiledAggregateQuery { kind: 'aggregate', pipeline }` with `[{ $match }, { $group }, { $project }, { $sort }]` stages

Translations:
- `WHERE col = $1` → `{ col: { $eq: value } }`
- `IN (...)` → `{ $in: [...] }`; `NOT IN` → `{ $nin: [...] }`
- `LIKE` patterns → `{ $regex: ..., $options: 'i' }` for case-insensitive (regex-special characters are escaped)
- `AND` / `OR` / `NOT` → `$and` / `$or` / `$nor`
- Aggregations → `{ $sum: '$col' }` / `{ $avg }` / `{ $addToSet }` etc. inside `$group`
- Keyset pagination → chained `$or` mirroring SQL row-tuple comparison; index-friendly with a compound index on `(sort_cols..., _id)`.

CDC via `collection.watch()`. The default `toRowDiff` translates `insert` / `update` / `replace` / `delete` operationTypes into `RowDiff`, ignores `drop` / `rename` / `invalidate`. ObjectId-like `_id` fields are coerced to string via `.toString()`. Resume tokens survive in `adapter.lastResumeToken()` for callers that want to checkpoint externally.

**Edge cases**
- Replica set required: change streams need `replSet` mode (Mongo 3.6+). Standalone Mongo doesn't support them — the adapter doesn't check; the `watch()` call will throw.
- Resync: Mongo doesn't expose a built-in "replay since version N." `resyncQuery` is optional — when omitted, every resync responds with `snapshot: true`. Production consumers wire it to an application-side outbox or oplog tail.
- `$addToSet` for `countDistinct` is unbounded; for huge cardinalities consumers should pre-stage with `db.distinct()`.

**Code surface in oneGrid**
`packages/adapters/mongo/src/{query,datasource,cdc}.ts`. README has the find/aggregate dispatch table + change-streams replica-set caveat.

**Test strategy**
23 unit tests: 14 query compiler (find + aggregate paths, regex escaping, anchored startsWith / endsWith, keyset $or expansion, multi-column grouping), 9 CDC (operationType dispatch, ObjectId coercion, resume-token tracking, snapshot fallback when no `resyncQuery`).

**References:** MongoDB find / aggregate — https://www.mongodb.com/docs/manual/reference/operator/aggregation-pipeline/ · Change streams — https://www.mongodb.com/docs/manual/changeStreams/ · Resume tokens — https://www.mongodb.com/docs/manual/changeStreams/#resume-tokens

## 12. Schema introspection (`@onegrid/introspect`)

**Architecture.** Three entry points + a SQL-data-type mapper. All composable on top of any adapter, all dependency-free except for `@onegrid/protocol`.

- `columnTypeFromSql(name)` — maps Postgres / MySQL / SQLite type names to the protocol's `ColumnType`. Recognizes bigint / int / smallint / tinyint, numeric / decimal, double / real / float, text / varchar / char / uuid / enum, timestamp `with`/`without time zone`, datetime, date, time, json / jsonb, bytea / blob / binary.
- `schemaFromSqlRows(rows)` — builds `Schema` from `information_schema.columns` rows. Tolerates `is_nullable` as boolean OR string (`'YES'` / `'NO'` / `'yes'` / `'no'` / `'true'` / `'false'`).
- `schemaFromSqliteRows(rows)` — same for `PRAGMA table_info(...)` (`notnull` is `0` / `1`).
- `columnsFromSchema(schema, opts)` — produces `MinimalColumnDef[]` (structurally compatible with `@onegrid/core`'s `ColumnDef`) with heuristic widths (id-shaped → 80, bool → 80, numeric → 120, timestamp → 160, utf8/json → 200, binary → 140), humanized displayNames (`snake_case` → "Snake Case", `camelCase` → "Camel Case"), and default formatters for bool / timestamp / json / binary. All heuristics accept per-column overrides.

**Edge cases**
- Postgres returns `timestamp with time zone` as a phrase (not `tz`-suffixed). The matcher checks both `tz` and the phrase.
- MySQL `ENUM('a','b')` type names include the values; the matcher hits `enum` substring → `utf8`.
- Composite types (PostGIS geometry, hstore, custom enums) fall through to `'unknown'`. Consumers handle them explicitly via per-column overrides.

**Code surface in oneGrid**
`packages/introspect/src/index.ts`. README has the heuristic table + adapter-specific quickstarts.

**Test strategy**
16 unit tests covering the Postgres / MySQL / SQLite type-name mappings, schema-from-rows transforms (boolean + string `is_nullable`, SQLite `notnull` 0/1), `columnsFromSchema` heuristics + override paths, and default formatters for bool / timestamp / json.

**References:** Postgres `information_schema.columns` — https://www.postgresql.org/docs/current/infoschema-columns.html · SQLite `PRAGMA table_info` — https://www.sqlite.org/pragma.html#pragma_table_info · MySQL `INFORMATION_SCHEMA.COLUMNS` — https://dev.mysql.com/doc/refman/8.0/en/information-schema-columns-table.html

## Critical-path implementation order (as shipped)

The v0.0.8 sequence ran in protocol-decisions-first / adapters-second order. Each protocol decision had to land before any real adapter shipped, otherwise the first adapter would have locked the wrong wire shape and we'd be paying for a v0.0.8.1 break:

1. **Keyset cursor canonicalization** — wire format for every adapter.
2. **Aggregation pushdown** — `BlockRequest.aggregations` shape + cache fingerprint participation.
3. **Real-time row diff protocol** — `RowDiff` envelope + resync semantics.
4. **Universal CDC adapter shape** — `CdcAdapter` interface + `createRowDiffStream` composition with the tracker.
5. **Optimistic mutations** — apply→commit/rollback orchestration using the same `pkey` + version contract as the row-diff stream.

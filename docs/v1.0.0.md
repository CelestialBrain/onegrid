# v1.0.0-rc — "stable"

**Status:** release-candidate scaffolding shipped. v1.0.0 final
requires the third-party security audit + adapter version bumps +
auto-generated API report.

**Date:** 2026-05-16

The stability milestone. v0.0.6 through v0.1.0 shipped feature
breadth; this RC locks the contracts adopters pin against, documents
the threat model, and expands the accessibility coverage from the
default in-memory mode to every playground mode + every UI panel that
mounts independent DOM (column tool, filters, group-by, formula bar).

## What ships in v1.0.0-rc

### 1. API surface freeze ([docs/SURFACE.md](SURFACE.md))

Four stability tiers — `@public`, `@beta`, `@internal`, `@deprecated`
— defined explicitly. Every export reachable through a package's
`exports` field will carry one of these tags by v1.0.0 final.

Public surface enumerated for the load-bearing packages:

- `@onegrid/core` — Grid + GridOptions + presets + ColumnDef type family + editor variants
- `@onegrid/protocol` — every wire-format type (most load-bearing surface)
- `@onegrid/data` — createColumnTable, FenwickHeights, BitmapSelection, sort/filter/group/pivot/aggregate
- `@onegrid/ssrm` — block fetcher, cursor codec, CDC stream, optimistic mutator
- `@onegrid/formula` — engine + AST + error codes
- v0.0.9 packages (plugin-kit, tokens, headless, intl, touch, worker-plugins) — all `@public`
- v0.0.10 packages (dbsp, sparklines, data-worker, new webgpu kernels) — `@public`
- v0.0.11 packages (mcp, temporal, ai, orm-sync, crdt, reactive) — `@beta` (new contracts; settle through v1.1/v1.2 before auto-promotion to `@public` at v1.3)
- v0.1.0 packages (webgpu-render, duckdb-join) — `@beta`

Internal surface (anything in `/internal/`, deep imports, `__tests__/`)
remains free to move in any release.

### 2. Semver policy ([docs/SEMVER.md](SEMVER.md))

Spells out exactly what counts as a breaking change. Quick summary:

- **Major** — remove/rename a `@public` export, change a `@public`
  signature, add a required field to a `@public` type, bump
  `PROTOCOL_VERSION`, raise the minimum Node / browser version
- **Minor** — add a `@public` export, add an optional parameter,
  change anything `@beta` (documented in CHANGELOG)
- **Patch** — bug fixes that don't change the surface

Adopter pinning guidance:
- Production: `^1.0.0` (range with fixed major)
- Library peer deps: `^1.0.0`
- Framework adapters: version-locked to their `@onegrid/core` major

Pre-v1.0.0 (everything currently `0.0.x`) is pre-stability —
breaking changes allowed at any release. Adopters running on `0.x`
should pin exact versions.

### 3. Security threat model ([docs/SECURITY.md](SECURITY.md))

The boundaries oneGrid defends and the ones it explicitly doesn't.

**In scope:**
- XSS via cell renderers (canvas writes text, not HTML; DOM overlays use textContent / React JSX)
- SQL injection in DB adapters (parameterized queries exclusively; column-name allowlists)
- Formula evaluation (AST evaluator; **no eval, no Function constructor**)
- Worker-plugin message validation
- Cross-source SQL composition in `@onegrid/duckdb-join` (literal escaping documented)
- MCP-proposed mutations never auto-apply (host's `onMutation` is the policy hook)
- CSP compatibility (`script-src 'self'` works; no `unsafe-eval`)

**Out of scope (adopter's responsibility):** authentication, authorization /
RLS, network transport security, CDC payload integrity, CRDT trust.

A vulnerability reporting contact, CVE policy, and audit-status
ladder are documented. v1.0.0 final adds the third-party audit
report link.

### 4. Expanded a11y axe-core coverage (`apps/benchmarks/src/a11y-modes.spec.ts`)

Original `a11y.spec.ts` ran axe-core only on the default in-memory
mode. The new spec runs the WCAG 2.1 A/AA gate on:

- In-memory / Formula / Pivot / Tree modes
- Column tool panel open
- Floating filter row + filters panel open
- Group-by active with sticky group rows

7 new tests, all green. Combined with the original 4 a11y tests:
**11 axe-core gates** verify zero critical/serious violations.

   bumped (commit `c893c8a`). Internal cross-refs were already
   `workspace:*` so no peer-dep range churn.
2. ✅ **Auto-generated API surface reports.** 43 baselines at
   `docs/api/<package>.api.md` + `pnpm api:check` CI gate via
   `scripts/generate-api-reports.mjs` (commit `7f4b8e4`). The
   generator auto-writes a per-package `api-extractor.json`;
   `@webgpu/types` is injected into the compiler config so the
   webgpu adapters' `GPUDevice` references resolve.

   252 previously-untagged exports tagged across 31 packages (commit
   `12bcee2`). `scripts/check-public-surface.mjs` is the CI gate;
   `scripts/tag-public-surface.mjs` is the idempotent bulk-tagger
   used to apply tags safely.
4. 🔵 **Third-party security audit.** External penetration test
   against the threat model in SECURITY.md. Audit report linked
   from v1.0.0 release notes. Pending commission.
5. ✅ **Fuzz harness in CI.** `fast-check` property tests for the
   four untrusted-input boundaries SECURITY.md calls out — formula
   parser/tokenizer, cursor codec, postgres filter compiler, and
   duckdb-join SQL escape (commit `c893c8a`). 12 specs across 4

7. 🔵 **Promotion of v0.0.11 + v0.1.0 packages from `@beta` to `@public`.**
   Each needs ≥ 1 minor of stability without breaking changes; the
   promotion happens automatically at v1.3 per the surface policy.

## What this milestone changes for the codebase

Before v1.0.0-rc, oneGrid was 22 published packages with no
stability contract. Adopters who shipped to production were
pinning exact versions and reading the changelog between bumps.

After v1.0.0-rc:

- The **public surface** is enumerated and documented
- The **semver policy** is published and unambiguous
- The **threat model** is explicit; in-scope defenses are tested,
  out-of-scope items are named so adopters can plan for them
- The **a11y gate** covers every UI mode the playground exposes, not
  just the default

v1.0.0 final ships when the verification (audit + auto-API-report +
fuzzing + version bumps) lands. The earliest realistic v1.0.0 final
is one full milestone away — probably bundled with v1.0.0 final +
v1.0.0.x bug-fix patches.

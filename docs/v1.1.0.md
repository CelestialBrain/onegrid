# v1.1.0 — "spreadsheet-grade"

**Status:** planned. Three chunks: OOXML round-trip, Excel-parity formula library, CRDT live collaboration. Effort spread is roughly 60 / 25 / 15.

**Date target:** TBD (single milestone; chunks can ship in parallel, see Ordering).

The v1.0.0 milestone closed the stability contract (surface freeze, semver, audit harness, real-DB integration, framework adapters). v1.1.0 turns the grid into a spreadsheet adopters can hand to analysts: open an `.xlsx` from email, type `=XLOOKUP(...)`, share the URL, and watch a coworker's cursor land on the same cell.

## What ships in v1.1.0

### Chunk A — `@onegrid/ooxml` (new package): ECMA-376 import/export

**Scope in.** New package `packages/ooxml/` separate from `@onegrid/export` (which keeps its SheetJS-backed `exportToXlsx` for the "I just want bytes" path). `@onegrid/ooxml` is the zero-runtime-deps, MIT, framework-agnostic ECMA-376 reader/writer. SheetJS stays an optional peer in `@onegrid/export` for adopters who already depend on it; `@onegrid/ooxml` does its own parsing so we control the surface and avoid the CPAL-1.0 / proprietary-license-rider concerns SheetJS has had.

ECMA-376 Part 1 (SpreadsheetML markup) + Part 2 (Open Packaging Conventions, i.e. the ZIP layout) are the in-scope reference; Parts 3 and 4 are deferred. Concretely, v1.1.0 round-trips:

| Feature                              | Read | Write |
| ------------------------------------ | ---- | ----- |
| Cell values: string / number / bool / date / inline-str / shared-str | y | y |
| Formulas (string preserved; cached value preserved) | y | y |
| Number formats (`numFmt`) including custom | y | y |
| Cell styles (`xf`, fonts, fills, borders, alignment) | y | y |
| Merged cells (`mergeCells`)          | y | y |
| Frozen panes (`pane` element)        | y | y |
| Column widths + hidden columns       | y | y |
| Row heights + hidden rows            | y | y |
| Defined names (workbook + sheet scope) | y | y |
| Tables (`tableParts`, `tableStyle`)  | y | y |
| Conditional formatting (`conditionalFormatting` + `dxf` differential styles) | y | y |
| Data validation (`dataValidations`)  | y | y |
| Hyperlinks                           | y | y |
| Comments / threadedComments          | y | y |
| Images (drawing.xml + media/)        | y | y (passthrough only — adopter supplies bytes) |
| Charts (`chart1.xml`)                | passthrough preserve | passthrough preserve |
| Pivot tables                         | passthrough preserve | passthrough preserve |

"Passthrough preserve" means: round-trip the XML parts untouched so opening + saving in oneGrid doesn't lose them, even though oneGrid can't render them yet.

**Scope out (v1.2/v1.3 candidates).**

- Native chart rendering (defer to v1.3; needs a charting subsystem).
- Native pivot-table read of pre-computed pivots (we can already pivot in `@onegrid/data`; reading Excel pivots is value-add but not required for round-trip).
- VBA / macros (`vbaProject.bin`) — preserve as opaque part, never execute. Document as out-of-scope in SECURITY.md.
- OLE objects, ActiveX controls — drop on read with a warning; never write.
- Encrypted / password-protected workbooks — explicit error, document the limitation.
- `.xlsm` / `.xlsb` — `.xlsx` only in v1.1.0. `.xlsb` (binary) is a v1.2 candidate.

**Package layout.**

```
packages/ooxml/
  src/
    index.ts                 // public surface
    package/                 // OPC layer (Part 2)
      zip.ts                 // streaming zip reader/writer; native, no jszip dep
      content-types.ts       // [Content_Types].xml
      relationships.ts       // _rels/*.xml.rels
      package.ts             // OpcPackage: parts + rels graph
    spreadsheet/             // SpreadsheetML layer (Part 1, §18)
      workbook.ts            // xl/workbook.xml: sheets, definedNames
      worksheet.ts           // xl/worksheets/sheetN.xml: rows, cells, panes, merges
      shared-strings.ts      // xl/sharedStrings.xml (interned strings)
      styles.ts              // xl/styles.xml: numFmts, fonts, fills, borders, cellXfs, dxfs
      tables.ts              // xl/tables/tableN.xml
      cond-format.ts         // sheet-embedded conditionalFormatting
      data-validation.ts     // sheet-embedded dataValidations
      comments.ts            // xl/comments*.xml + threadedComments
      drawing.ts             // xl/drawings/*.xml (image anchors only; chart passthrough)
    xml/
      sax.ts                 // streaming SAX-ish reader (no DOM blow-up on big sheets)
      writer.ts              // XML writer with attribute escaping; uses `xml` builder; no eval
    schema/
      validate.ts            // post-parse structural validation; rejects malformed before render
      types.ts               // SpreadsheetML AST types (the in-memory shape)
    convert/
      to-grid.ts             // SpreadsheetML AST → GridOptions + ColumnTable
      from-grid.ts           // GridOptions + ColumnTable → SpreadsheetML AST
    __tests__/
      fixtures/              // .xlsx files committed as binary; round-trip oracle
      round-trip.test.ts     // open → save → open; AST equality (excluding tracked-noise fields)
      excel-fixtures.test.ts // open .xlsx written by Excel (LibreOffice fallback); render parity
      libreoffice.test.ts    // open .xlsx written by LibreOffice; same parity check
      sax.fuzz.test.ts       // fast-check: random byte sequences never crash the SAX reader
      zip.fuzz.test.ts       // fast-check on zip records; bomb-resistant
    bundle-budget.json       // 20 KB gz target for full read+write
```

**Surface impact.**

```ts
// @onegrid/ooxml — all @beta in v1.1.0 (new contract; promote to @public at v1.3)
@beta export function readXlsx(bytes: Uint8Array | ArrayBuffer): Promise<Workbook>
@beta export function writeXlsx(workbook: Workbook): Promise<Uint8Array>
@beta export function workbookToGrid(wb: Workbook, sheetName?: string): { options: GridOptions; table: ColumnTable }
@beta export function gridToWorkbook(opts: { options: GridOptions; table: ColumnTable; sheetName?: string }): Workbook
@beta export type Workbook, Worksheet, Cell, Style, NumberFormat, ConditionalFormat, DataValidation, DefinedName, Table
```

Add to docs/SURFACE.md v1.1.0 surface section; mark `@beta` per the v0.0.11/v0.1.0 precedent. Promotion to `@public` at v1.3.

**Test strategy.**

- **Fixture round-trip suite.** Commit ~20 `.xlsx` files (~200 KB total) generated by Excel and LibreOffice covering each feature row in the matrix above. The oracle: read → write → read produces an AST equal to the first AST (modulo tracked-noise fields like `lastModifiedBy`, `dcterms:modified`).
- **Excel-written + LibreOffice-written corpus.** Two writers, same test. Catches the "we only round-trip our own output" failure mode.
- **Property tests on SAX + zip.** `fast-check` generates random byte sequences and random valid-but-pathological XML structures (deeply nested, huge attribute counts, BOM markers). Must not crash, must produce a typed error.
- **Zip-bomb gate.** Reject archives whose decompressed size exceeds 256 MB or whose compression ratio exceeds 100:1. Tested with a synthetic bomb fixture.
- **No-`eval` proof.** Same lint rule the formula evaluator already passes — no `Function`, no `eval`, no `setTimeout(string)`.

**Effort:** ~35 person-days. The ZIP/OPC + SAX writer + style preservation are the heavy parts; the cell-type cases are mechanical.

### Chunk B — `@onegrid/formula` Excel-parity function library

Current `packages/formula/src/functions.ts` ships ~30 functions (math basics + IF/AND/OR + LEN/UPPER/LOWER/MID/FIND/SUBSTITUTE + YEAR/MONTH/DAY/TODAY/NOW). Excel ships ~480 in the latest Microsoft 365; "spreadsheet-grade" means hitting the subset analysts actually use plus the modern dynamic-array functions.

**Scope in (v1.1.0 target: ~250 functions).** One file per category under `packages/formula/src/functions/`:

| ------------------------------ | ---------------------------------- |
| `math.ts`                      | +50: PRODUCT, SUMSQ, SUMPRODUCT, GCD, LCM, EXP, LN, LOG, LOG10, RADIANS, DEGREES, sin/cos/tan + asin/acos/atan/atan2, sinh/cosh/tanh, RAND, RANDBETWEEN, RANDARRAY, SIGN, TRUNC, ROUNDDOWN, ROUNDUP, MROUND, EVEN, ODD, SQRTPI, FACT, COMBIN, PERMUT, BASE, DECIMAL |

**Scope out / deferred.**

- **Dynamic-array spilling semantics.** FILTER/SORT/UNIQUE return arrays today; the evaluator already returns array values. The "spill into neighboring cells" UI behavior is a separate v1.2 grid-side feature (needs spill-range tracking and `#SPILL!` error in the dependency graph). v1.1.0 ships the functions returning arrays; consuming an array in a single-cell formula uses the first element (matches legacy Excel behavior).
- **LET / LAMBDA.** Real implementation requires lexical-scope extension to the parser. Earmark for v1.2; document as `@beta` placeholder if shipped.
- **REGEX.TEST / REGEX.REPLACE / REGEX.EXTRACT.** Microsoft shipped these in 2024; require a security review (catastrophic-backtracking attack surface). Deferred to v1.2 pending review.
- **CUBE.* functions.** Out of scope; OLAP integration is its own milestone.
- **Engineering / Database categories.** Documented as out for v1.1.0.

**Surface impact.**

No new exports — `registerFormulaFunction` is already the extension point, and every function lives behind the existing `getFunction()` lookup. Two ancillary `@beta` additions to `packages/formula/src/index.ts`:

```ts
@beta export const FORMULA_FUNCTIONS_VERSION = '1.1.0'      // bumps on library churn
@beta export function listFormulaFunctionsByCategory(): Record<string, string[]>
```

Verify the existing `@public` `listFormulaFunctions()` stays stable (it's a one-way string list; adding entries is non-breaking per docs/SEMVER.md).

**Test strategy.**

- **One `.test.ts` per category file.** Each function has at least: happy path, edge cases (empty range, all-error range, type-coercion), Excel-parity cases lifted from the public ECMA-376 §18.17 examples and Microsoft's public function docs (cite the URLs in the test file header for traceability — never copy text).
- **Cross-validation fixture.** A 200-row `.xlsx` containing one formula per function with its Excel-computed result in the next column. The test reads the fixture via `@onegrid/ooxml` (Chunk A!), evaluates each formula through our engine, asserts result equality within `1e-10` for floats. This is the strongest "we match Excel" gate we can build without shipping a copy of Excel.
- **Property tests on the financial family.** PMT/PV/FV/NPV satisfy known algebraic identities (`PV(rate, n, PMT(rate, n, PV)) === PV`); `fast-check` generates rate/period/principal triples and asserts the identities hold within tolerance.
- **Fuzz the parser is already in place** — no expansion needed; new functions are evaluator-side only.

**Effort:** ~15 person-days, frontloaded on stats + financial (the two with subtle floating-point traps). The lookup family is the trickiest because INDEX/MATCH and XLOOKUP need to honor `CellResolver`'s range protocol.

### Chunk C — CRDT live-collab integration

`@onegrid/crdt` already ships the **diff plumbing** (Yjs Y.Map observe → `RowDiff`, Automerge heads-diff → `RowDiff`, `applyLocalToYjs`). What it does NOT ship: **awareness/presence** (who else is here, where is their cursor/selection), **provider wiring** (the actual WebSocket/WebRTC sync), **collaborative cell-edit conflict resolution** (right now two simultaneous Y.Map.set() calls last-write-wins at the field level; we want per-field LWW with vector-clock-aware merge for nested cell metadata).

**Scope in.**

- **Presence channel.** Wrap `awarenessProtocol.Awareness` (y-protocols) and expose a typed contract:

  ```ts
  @beta export interface PresenceState {
    readonly clientId: number
    readonly user: { id: string; name?: string; color?: string }
    readonly selection?: SelectionSnapshot
    readonly activeCell?: { rowKey: string; columnId: string }
    readonly editingCell?: { rowKey: string; columnId: string }
  }
  @beta export function bindYjsPresence(opts: { awareness: AwarenessLike; user: ... }): PresenceBridge
  @beta export interface PresenceBridge {
    setSelection(s: SelectionSnapshot | null): void
    setActiveCell(c: { rowKey: string; columnId: string } | null): void
    setEditing(c: { rowKey: string; columnId: string } | null): void
    onPeers(handler: (peers: ReadonlyMap<number, PresenceState>) => void): () => void
    close(): void
  }
  ```

- **Field-level granularity for cell edits.** Currently `applyLocalToYjs` writes whole row fields via `map.set(key, fields)` — two users editing different columns of the same row stomp each other. Replace with a Y.Map-per-row layout under an opt-in `granularity: 'row' | 'field'` flag on `bindYjsRows`. Field mode writes `outer.get(rowKey).set(columnId, value)`, so concurrent edits to different columns commute by Y.Map's own merge.
- **Optimistic-mutator integration.** `@onegrid/ssrm`'s `createOptimisticMutator` already produces local `RowDiff`s. Wire a `crdtTransport` option that pipes those diffs through `applyLocalToYjs` instead of (or alongside) the HTTP/SSE transport.
- **Selection-rendering hook in `@onegrid/core`.** A new `presence` GridOption that takes a `PresenceBridge`-shaped port (structural; no runtime import of `@onegrid/crdt`). The renderer draws peer-color outlines on cells/ranges peers have selected, and a small avatar/name badge floats at the active-cell corner. Renders through the existing DOM overlay layer — no canvas changes, no WebGPU changes.
- **Conflict resolution doc.** New `docs/COLLAB.md` describing the three layers (row-add/delete via Y.Map causality, field-level cell edits via per-cell Y.Map, awareness as ephemeral) and what guarantees each gives. Be explicit about what's NOT guaranteed (cell-text character-level CRDT for in-progress edits is deferred — uses last-writer-wins on commit).

**Scope out / deferred.**

- **Per-character text-cell CRDT (Y.Text for cell strings).** Real collaborative typing inside a single cell. Big design surface (cursor preservation under remote insert, IME interactions). Defer to v1.2 as `@onegrid/crdt/text` sub-export.
- **Provider implementations.** We don't ship a WebSocket server, a WebRTC signaller, or any transport. Adopters bring `y-websocket`, `y-webrtc`, `@hocuspocus/provider`, or their own. Document the three popular options in `docs/COLLAB.md`; tests use an in-process fake provider.
- **Server-side authority / permission gating.** Out of scope — `docs/SECURITY.md` already names "CRDT trust" as adopter-owned. Mention again in `docs/COLLAB.md`.
- **Automerge presence.** Automerge doesn't have a built-in awareness protocol equivalent. Document a structural `AwarenessLike` shape so adopters who wire one (e.g. via `@automerge/automerge-repo`'s ephemeral messages) can plug in, but don't ship an Automerge presence binding.

**Package layout.**

```
packages/crdt/src/
  index.ts                       // re-exports
  yjs/
    rows.ts                      // existing bindYjsRows; gain `granularity` option
    rows-field.ts                // new: per-field Y.Map layout + observeDeep wiring
    presence.ts                  // new: bindYjsPresence around AwarenessLike
    awareness-types.ts           // structural AwarenessLike interface
  automerge/
    rows.ts                      // existing bindAutomergeRows (moved out of index.ts)
  __tests__/
    rows-field.test.ts           // concurrent field edits commute
    rows-field.fuzz.test.ts      // fast-check: random interleavings on N peers commute
    presence.test.ts             // selection/active cell propagation across fake peers
    integration.test.ts          // 3 peers, 100 ops each, random partition+reconnect, converge
```

`packages/core/src/`:

```
features/presence/
  index.ts                       // PresenceLike port + GridOption integration
  overlay.tsx                    // DOM overlay: peer-color cell outlines + badges
  __tests__/overlay.test.tsx
```

**Surface impact.**

```ts
// @onegrid/crdt — all @beta
@beta export interface AwarenessLike { ... }
@beta export interface PresenceState { ... }
@beta export interface PresenceBridge { ... }
@beta export function bindYjsPresence(opts): PresenceBridge
@beta export interface BindYjsRowsOptions { ...; granularity?: 'row' | 'field' }  // ADD field

// @onegrid/core — @public additions (load-bearing; commit before locking)
@public export interface GridOptions { ...; presence?: PresenceBridge | null }
```

Document in `docs/SURFACE.md` v1.1.0 section. The `GridOptions.presence` field is `@public` because `GridOptions` itself is `@public`; per docs/SEMVER.md "adding optional fields to `@public` types" is allowed in a minor.

**Test strategy.**

- **Property test: concurrent commutation.** `fast-check` generates N peers × M operations (insert/update/delete on overlapping row keys and overlapping field keys). Apply each peer's ops in random order to a fresh document, sync, assert all peers converge to the same state.
- **Network-partition test.** Three peers, fake provider with controllable partition. Each peer makes 50 edits while partitioned, partition heals, assert convergence.
- **Presence-fanout test.** Three peers, peer A changes selection 10 times, assert peers B and C see each change in order with peer A's clientId attached.
- **`@onegrid/core` overlay test.** Drive `presence` GridOption with synthetic peer states; assert correct cell outlines and badge placement (existing Playwright harness in `apps/benchmarks/`).

**Effort:** ~10 person-days. Most of the unknowns are at the `AwarenessLike` boundary — y-protocols' `Awareness` is well-typed but its update events fire as `{added, updated, removed}` arrays of clientIds, and we have to read state out of `awareness.getStates()` each time. Manageable.

## Ordering / dependencies

```
Chunk A (OOXML)  ────────────────────────────────────┐
                                                     ├─→ Chunk B's Excel-parity fixture
Chunk B (formula library) ───────────────────────────┘   test depends on A's reader

Chunk C (CRDT) ──── independent; can ship first if a Yjs adopter is waiting
```

- **Chunk A and Chunk C are independent** and can be worked in parallel by separate hands.
- **Chunk B's Excel-cross-validation suite** needs Chunk A's `readXlsx`. The functions themselves don't — most function tests are pure-JS and can land first. Schedule: ship Chunk B function code in early weeks, slot the cross-validation fixture suite in once Chunk A's reader is green.
- **No chunk modifies `@onegrid/protocol`,** so no `PROTOCOL_VERSION` bump and no major-version churn for adapters.

## Open questions (need user input before implementation)

1. **OOXML: own parser vs. extend SheetJS?** Plan above assumes own parser (license control, surface control, ~20 KB budget). SheetJS reroute would save weeks but pulls a 600 KB peer dep and historical license complexity. Confirm own-parser.
2. **OOXML: defer charts/pivots to v1.3, or attempt read-only render in v1.1.0?** Plan assumes passthrough preserve only. Native chart render is its own ~30-day chunk.
3. **Formula library count target.** Plan targets ~250 functions (analyst coverage). True Excel parity is ~480. Confirm 250 is enough for "spreadsheet-grade" or push to ~400 (financial + engineering + database categories).
4. **CRDT field-granularity default.** Should `bindYjsRows` default to `granularity: 'field'` (better collab UX, breaks existing row-shape consumers) or `granularity: 'row'` (preserves current behavior, opt-in for field mode)? Plan assumes opt-in for v1.1.0, flip default at v1.3.
5. **Presence sub-path or first-class GridOption?** Plan puts `GridOptions.presence` at the top level. Alternative: gate behind `gridOptions.experimental.presence` until v1.2. Top-level adds public-surface commitment now.
6. **`@onegrid/formula` sub-path exports.** Are adopters ready for sub-path imports (breaking change for bundlers configured without `exports`-field resolution)? Default barrel preserves the existing import path, so this is additive — confirming for paranoia.
7. **Excel-parity fixture corpus.** Do we generate the .xlsx fixtures with a paid Excel license (one of us has one) or stick to LibreOffice Calc (free, occasionally diverges from Excel in numFmt rounding edge cases)? Affects test-time stability.

# v0.0.10 — "performance"

**Status:** all 8 items shipped.

**Date:** 2026-05-15

Performance-focused milestone. The goal: push the per-frame work
ceiling above what commercial grids can hit by addressing six
profile hot spots — column iteration cost, scroll-fling jitter,
formula precision at int64, idle-rAF battery drain, sort/filter
on the render thread, and pre-compute for incremental views.

## Critical-path order

Same hardest-to-retrofit-first principle.

1. **Column virtualization** — narrows render loops to visible
   columns. Lands first because it doesn't touch any contract.
2. **Adaptive overscan** — EMA + direction-aware split. Lands second
   because it tunes the same renderer the column-virt loop now
   operates on; benefits compound.
3. **BigInt-safe formula path** — coerce + arithmetic dispatch.
   Independent of rendering; sequenced here because adapter int64
   integration tests want it in place.
4. **rAF discipline + dirty-state gate** — stops the always-on rAF
   loop. Small change, large idle-battery win.
5. **Web Worker offload** — `@onegrid/data-worker` reuses the v0.0.9
   `@onegrid/worker-plugins` framework. Wins compound with column-
   virt: visible columns repaint at 60 FPS while a worker thread
   sorts the off-screen state.
6. **DBSP operator algebra spec** — `docs/dbsp-spec.md`. Establishes
   the contract item 7 implements.
7. **`@onegrid/dbsp`** — reference implementation of the spec.
   Source / map / filter / union / distinct / groupAgg / topK-sort.
8. **`@onegrid/sparklines`** — in-cell charts. Independent; sequenced
   last because it's the smallest cognitive load.

## Per-item

### 1. Column virtualization

`Grid.visibleColumnRangeInBand(colStart, colEnd, horizontalOffset)`
returns `{ first, last, xStart }`. Render loops in `drawRows` +
`drawHeader` iterate only `[first..last]` instead of the full column
array.

Before: a 200-column grid showing 12 columns iterated 200 columns
× viewport rows per frame, accumulating `x += w` for the 188
off-screen columns (which the viewport-test then no-op'd).

After: 12 × viewport rows. The off-screen iteration cost is zero.

Tree-row indent + chevron predicate `col === colStart && colStart === 0`
intentionally preserved — when scrolled past column 0, the indent
disappears with the off-screen column, which is the correct visual.

6 new unit tests + the existing 23 grid tests still green.

### 2. Adaptive overscan

Replaces a 3-tier static `|Δscroll|` window with:

- **`velocitySmoothed`** — EMA at α=0.4 of per-event `|Δscroll|`.
  Damps single-frame trackpad-inertia spikes; ~7 frames to
  converge at 60 fps.
- **`scrollDirection`** — `-1` / `0` / `+1` tracking travel sign.
- **`adaptiveOverscan()` → `{ ahead, behind }`** — magnitude from
  velocity tier (stationary 2/2 → low 4/2 → mid 8/3 → high 16/4);
  direction swaps which side gets the bigger window.

The render loop now reads `ahead` and `behind` independently, so the
pre-fetch window faces travel. 6 new tests including the EMA decay
property.

### 3. BigInt-safe formula path

`@onegrid/formula/coerce` gains `toNumeric(v)` that returns `bigint`
when value fits losslessly:

- `bigint` → `bigint`
- Integer `Number` outside safe range → `BigInt(v)`
- `boolean` → `0n` / `1n`
- All-digit string → `BigInt(string)`
- Anything else → `Number` (same as `toNumber`)

New arithmetic helpers (`addNumeric`, `subNumeric`, `mulNumeric`,
`divNumeric`) dispatch `bigint, bigint → bigint`. Mixed or non-exact
division falls back to Number (BigInt can't represent fractions).
Division by zero on either type → `DIV_ZERO`.

`evaluator.ts` routes `+ - * /` through the new helpers. `^` stays
Number — BigInt exponentiation requires both bigint AND Excel allows
fractional/negative exponents BigInt can't carry.

21 new tests; 87 existing tests still green (108 total).

### 4. rAF discipline + dirty-state gate

Before: `tick()` re-armed `requestAnimationFrame` unconditionally.
A static grid ran the rAF loop at 60 Hz forever — fine for
correctness, terrible for mobile battery and GPU power.

After: re-arm only if `stillDirty` is true. `stillDirty` covers:

- In-flight scroll mismatch (smooth-scroll settle)
- Active cell editor needing layout sync
- Floating filter band

For everything else, `scheduleRender()` restarts the loop on demand
from every state-mutating callsite (cell-change, mutation, theme
swap, etc.).

Full dirty-rect partial repaint deferred to v0.0.10.x — `render()`'s
correctness depends on single-pass top-down repaint for border
continuity; the per-region clipping needs a careful rework.

### 5. Web Worker offload

`@onegrid/data-worker` reuses `@onegrid/worker-plugins` (v0.0.9
item 8). Two entrypoints:

- `@onegrid/data-worker` (host) → `createDataWorker({ worker })`
- `@onegrid/data-worker/worker` (worker) → bundles
  `definePluginWorker` with the four handlers (`sort` / `filter` /
  `group` / `pivot`)

Authors construct their own Worker (Vite's `new Worker(new URL(...),
{ type: 'module' })`, webpack `worker-loader`, etc.) so we don't
pin a build tool. Bundle: host 0.60 KB gz, worker 0.25 KB gz
(per-feature delta; the actual worker bundle inlines `@onegrid/data`).

2 tests via in-process worker pair. The real-Chromium perf win
(1M-row sort moving from render thread to worker) is a v0.0.10.x
benchmark to add.

### 6. DBSP operator algebra spec

`docs/dbsp-spec.md` — 7 sections covering Z-sets, streams,
integration/differentiation, lifting, the DBSP incrementalization
theorem (Budiu et al., VLDB 2023), each operator's signature, IR
shape, wire format, state shapes, and test strategy.

Establishes the contract item 7 implements + the future work item 7
defers to v0.0.10.x (full join, full sort, checkpoint/resume).

### 7. `@onegrid/dbsp`

Operators implemented:

| Op           | applyDiff cost     | Notes                                   |
| ------------ | ------------------ | --------------------------------------- |
| `source`     | O(\|Δ\|)           | Pass-through; maintains snapshot        |
| `map`        | O(\|Δ\|)           | Project each row                        |
| `filter`     | O(\|Δ\|)           | Predicate keep/drop                     |
| `union`      | O(\|Δ\|)           | Two-input pointwise Z-set add           |
| `distinct`   | O(\|Δ\|)           | Coalesces weights to {-1, +1}           |
| `groupAgg`   | O(\|Δ\| · #aggs)   | count/sum/avg/min/max; per-column state |
| `topK` sort  | O(N log K) baseline | Heap-based incremental coming in 10.x   |

Per-(group, source-column) state shape for groupAgg — two aggs over
different columns don't double-count; multiple aggs over the same
column share state. Empty groups (count → 0) get retracted.

14 tests including the incrementalization-theorem property
verifying `filter`'s incremental output matches the batch
snapshot path byte-for-byte. Budget: 2.10 / 4.00 KB gz with
headroom for the deferred operators.

Deferred to v0.0.10.x:

- **Full join** — delta-join with indexed state on both sides
- **Full sort** — red-black tree incremental sorted index
- **Checkpoint / resume** — serialize operator state to survive
  process restart

### 8. `@onegrid/sparklines`

Three chart kinds — `line` / `bar` / `winloss`. Pure-function API
that draws into a Canvas2D rect; a `createSparklineRenderer`
factory drops straight into `ColumnDef.renderer`.

Features: optional area fill (auto-alpha from stroke color), min/max
extrema dots, caller-supplied y-domain for comparable rows, zero/
auto baseline detection for bars, configurable bar gap + padding.

9 tests. 1.42 / 2.00 KB gz. Zero deps.

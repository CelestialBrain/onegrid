# v0.0.11 — "moats"

**Status:** all 6 items shipped.

**Date:** 2026-05-16

The differentiation milestone. Each item lands oneGrid in a niche no
other open-source grid occupies — Model Context Protocol surface for
LLMs, time-travel over the row stream, BYO-LLM natural-language intent
parsing, typed ORM sync over the v0.0.8 CDC layer, CRDT collaborative
editing, and a Salsa-style reactivity substrate.

## Critical-path order

1. **MCP server** — discrete, public-spec-driven, defines the surface
   item 3 plugs into.
2. **Temporal log** — independent layer over the v0.0.8 RowDiff
   stream. Lands before CRDT so the CRDT bridges can feed temporal
   without circular deps.
3. **AI integration** — composes with item 1 (MCP server tools) and
   the protocol's typed Filter/Sort shapes.
4. **ORM sync** — bridges v0.0.8 CDC into ORM-typed rows. Discrete.
5. **CRDT bridges** — emits RowDiff like the CDC adapters, so any
   downstream (DBSP, temporal, optimistic mutator) consumes it without
   translation.
6. **Reactive substrate** — Salsa-style. Substrate-only this
   milestone; the formula-engine + derived-views migration onto it
   lands in v0.0.11.x patches.

## Per-item

### 1. `@onegrid/mcp` — MCP server surface

Anthropic's Model Context Protocol (2024) JSON-RPC shape for LLM↔tool.
Exposes six resources and six tools:

| Resources                | Tools                |
| ------------------------ | -------------------- |
| `grid://columns`         | `set_sort`           |
| `grid://sort`            | `set_filter`         |
| `grid://filter`          | `scroll_to_row`      |
| `grid://selection`       | `read_block`         |
| `grid://viewport`        | `select_range`       |
| `grid://row/{rowIndex}`  | `propose_mutation`   |

Server is transport-agnostic — adopters plug `createMcpServer().handle(req)`
into the official `@modelcontextprotocol/sdk-typescript`, a custom
WebSocket, or an eval harness. No SDK pin.

**Mutation discipline:** `propose_mutation` NEVER auto-applies. It
routes through `bridge.onMutation`; the host decides apply / queue
for human review / deny. Denial throws surface as MCP error code
-32005 (`DENIED`). Auto-applying LLM edits to live data is dangerous;
making the application path explicit means the host owns the safety
policy.

14 tests. 2.29 / 3.00 KB gz.

### 2. `@onegrid/temporal` — time-travel

Append-only diff log layered over the v0.0.8 RowDiff stream. The diff
versions are already monotonic; this package adds:

- `append(diff)` — record into the log
- `snapshotAt(version)` — reconstruct state at any past version
- `diffBetween(from, to)` — net diff (undo/redo recipe)
- `branch(fromVersion)` — fork a sub-log from history
- `invertDiff(diff, prevSnap)` — produce the inverse for undo
  - insert → delete
  - delete → insert with previous row contents
  - update → update of just the touched fields

Memory bounds caller-controlled: `anchorInterval` (default 1000)
takes periodic snapshot anchors so `snapshotAt(V)` replays at most
N diffs forward; `retentionVersions` drops older entries.

13 tests including a 20-diff anchor-replay path and an end-to-end
undo-via-diffBetween+invertDiff recipe. 1.78 / 2.00 KB gz.

### 3. `@onegrid/ai` — natural-language intent

BYO-LLM contract — caller supplies `{ complete(prompt) → string }`;
this package owns the prompt shape, JSON schema, and response
validation. Output is strictly typed against `@onegrid/protocol`'s
`FilterNode` / `SortField`.

Four intent kinds: `filter`, `sort`, `formula`, `mutation`. All
compose with the v0.0.8 mutator, v0.0.11 MCP server, and the
standard grid `setSort` / `setFilter` API.

Heuristic fallback: `parseIntentHeuristic(text, columns)` handles
obvious cases (`sort by amount desc`, `amount >= 100`, etc.) with
regex — useful for skipping the model latency on clearly-structured
input or for an offline mode.

Validation throws named codes:
- `OG_AI_INVALID_JSON`
- `OG_AI_INVALID_INTENT`
- `OG_AI_INVALID_FILTER` / `OG_AI_INVALID_SORT_FIELD`

These are deliberate — don't trust a model to invent column names or
operators; surface "I didn't understand that" to the user.

16 tests. 2.17 / 3.00 KB gz.

### 4. `@onegrid/orm-sync` — live ORM sync

The v0.0.8 CDC adapters already emit RowDiffs; this package adds the
typed-row glue. Three layers:

1. `OrmModelDescriptor<TRow>` typed by `keyof TRow`
2. Extractors:
   - `extractFromDrizzle` — Drizzle's `getTableColumns` shape
   - `extractFromKysely` — explicit schema (type-level only)
   - `extractFromPrisma` — Prisma DMMF field shape
3. `bindOrmSync({ cdc, model, onDiff })` — wraps a `CdcAdapter` so
   callbacks fire with `TypedRowDiff<TRow>` instead of raw `RowDiff`

Type mapping: int → `int32`, BigInt → `int64`, Float/Double → `float64`,
Decimal → `decimal`, String/varchar/text → `utf8`, Boolean → `bool`,
DateTime → `timestamp_tz`, Date → `date32`, Json → `json`,
Bytes/bytea/blob → `binary`.

No ORM dep pinned — extractors take structural runtime-metadata
shapes each library exposes.

9 tests. 1.02 / 3.00 KB gz.

### 5. `@onegrid/crdt` — collaborative editing

Two CRDT bridges, both translating document changes into RowDiff
streams identical to v0.0.8 CDC output:

- **Yjs (YATA lineage):** `bindYjsRows({ map, onDiff })` observes a
  Y.Map and translates `YMapEvent` change records.
  `applyLocalToYjs(map, diff)` writes local edits that propagate via
  Yjs sync exactly like remote changes.
- **Automerge:** `bindAutomergeRows({ doc, watcher, onDiff })` takes
  structural doc + watcher ports; runs a shallow snapshot diff
  between subscribe firings.

Neither library is imported. Adopters pass structural ports
(`YMapLike`, `AutomergeDocLike` + `AutomergeWatcherLike`) so the
package stays dep-free and version-agnostic.

8 tests via in-process fakes. 0.79 / 2.00 KB gz.

### 6. `@onegrid/reactive` — Salsa-style substrate

On-demand memoization with revision-counter invalidation and the
**backdating** property. Ported from the public salsa-rs design.

Three primitives:
- `Database` — owns revision counter, input slots, memo cache
- `defineInput(key, initial, eq?)` — input slot; writes bump revision
  only when value differs by the (caller-supplied) comparator
- `defineQuery(key, compute, { eq?, hashArgs? })` — memoized query;
  auto-tracks dependencies via thread-local trace stack

**Backdating** is the property that distinguishes Salsa from plain
dirty-marking. When a query recomputes and its NEW value equals its
previous cached value, the memo keeps its old `computedAt` revision.
Downstream queries see upstream as "unchanged since R" and skip their
own recompute. A 1000-node graph with one leaf changing — where the
change happens to re-derive to the same value — runs O(1) recomputes
instead of O(N). That's the property that lets rust-analyzer stay
responsive while you type.

Substrate-only this milestone. Formula engine + derived views +
column-tool panel migration lands in v0.0.11.x patches; the
Adapton-based formula engine stays canonical until then.

10 tests including the backdating cascade-protection property
(downstream computes exactly once across two input changes that both
re-derive to the same upstream value). 1.72 / 2.00 KB gz.

## What this milestone changes

Before v0.0.11, oneGrid was a fast canvas-based grid with strong CDC
+ formula support. After v0.0.11:

- LLMs can read and act on grid state through a standard contract
  (MCP)
- Every row mutation is undoable / branchable / time-travelable
- The grid has typed sync with Drizzle, Kysely, Prisma models
- Two users can edit the same row over Yjs or Automerge and the diffs
  flow through the same plumbing as a single-user CDC stream
- The reactivity substrate is in place for the v0.0.11.x formula
  migration

These are the **moats** entries on the roadmap: each one is something
no other open-source grid ships. Together they make oneGrid the only
grid where you can wire an LLM to a collaborative spreadsheet over a
live ORM, time-travel through the edit history, and have the
reactivity substrate keep paint-loop FPS at 60 throughout.

## Deferred to v0.0.11.x

- Formula engine migration onto `@onegrid/reactive` substrate
- Derived-views package using the substrate
- Column-tool panel reactivity migration
- Automerge bridge with heads-based diff walking (current is
  shallow snapshot diff — fine for small workspaces, won't scale to
  thousands of rows)

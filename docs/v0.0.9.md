# v0.0.9 — "extensibility + ergonomics"

**Status:** items 1–8 shipped; items 9–16 deferred pending a second
research pass.

**Shipped:** 8 of 16 milestone items.

**Date:** 2026-05-15

This is the post-hoc Implementation Patterns Report for v0.0.9. The
milestone goal was "stop hard-coding the things adopters need to
customize" — themes, locales, aggregators, filter operators, density,
touch, lifecycle, and config shape were all built into core through
v0.0.8. v0.0.9 inverts that: there is one plugin framework
(`@onegrid/plugin-kit`), and every customization surface registers
into it instead of forking.

The eight shipped items also stay aggressively under-budget: the
total cost of v0.0.9 across new packages is **8.8 KB gz** (plugin-kit
2.1 + tokens 1.7 + headless 2.1 + intl 2.7 + touch 2.0 + worker
1.0). Per-feature bundle budgets gate further growth.

## Critical-path sequencing (what shipped in order, and why)

The same "hardest-to-retrofit-first" rule as v0.0.6 / v0.0.7 / v0.0.8.

1. **`@onegrid/plugin-kit`** — facets, compartments, registries.
   Everything else registers through this. If it shipped second,
   themes/intl/aggregators would each have to refactor.
2. **`@onegrid/tokens`** — DTCG 2025.10 bundles. Registers through
   the theme registry from #1.
3. **`defineGridOptions` nested config** — non-invasive: the
   internal `Grid` class continues to consume flat `GridOptions`;
   the factory only normalizes input + warns on flat. Could ship
   anywhere in the milestone; landed third because of test surface.
4. **`@onegrid/headless`** — Lit-`ReactiveController` lifecycle on
   top of `Grid`. Has to land before framework adapters refactor
   onto it; lands fourth so it can consume the nested options
   shape.
5. **Per-feature bundle budgeting** — the CI gate. Lands mid-stack
   so subsequent items (intl, touch, worker) get measured the
   moment they land.
6. **`@onegrid/intl`** — Intl.* wrappers + ICU MessageFormat subset
   + RTL helper. Registers locale catalogs into plugin-kit.
7. **`@onegrid/touch`** — Pointer Events recognizer + touch CSS +
   VirtualKeyboard adapter + inputmode mapping.
8. **`@onegrid/worker-plugins`** — second trust tier for
   user-supplied compute. Lands last because it depends on
   plugin-kit's registry shape stabilizing.

## Per-item implementation notes

### 1. `@onegrid/plugin-kit` — 16 tests, 2.09 KB gz

**Architecture.** Facets combine many inputs into one output.
Extensions are opaque tokens returned by `facet.of(value)`,
`compartment.of(ext)`, or `registry.register(id, value)`. The grid
never inspects an extension structurally — it resolves through a
`PluginState`. Five precedence tiers (`highest` / `high` / `default`
/ `low` / `lowest`); within a tier, registration order. Auto-dedup
by `(facet, value identity)`.

**Compartments** wrap a sub-extension in a swappable slot.
`state.reconfigure({ replace: new Map([[comp, nextExt]]) })` produces
a new state with the inner extension swapped — the rest of the tree
is reused. That's the theme-swap path.

**Ten typed registries** ship in `plugin-kit`: cellRenderer,
cellEditor, exporter, dataSource, theme, formulaFunction,
aggregator, filterOperator, columnTool, i18nCatalog. Each is a
`PluginRegistry<T>` whose internal facet combines
`{ id, value }` registrations into a `Map<string, T>` (first wins
on id collision; combine with precedence to give users override
power).

**`interfaceVersion`** is a single integer. Plugins declare the
version they were authored against via `definePlugin({ name,
interfaceVersion, extensions })`; mismatched versions throw
`[OG_PLUGIN_INTERFACE_VERSION]` at module load. v0.0.9 ships as v1.

**`PluginContext`** is the narrow surface plugins receive — `facet`,
`resolve`, `interfaceVersion`. No DOM, no canvas, no raw grid
internals. Keeps plugins portable across the worker boundary
(item 8).

**Reference.** Marijn Haverbeke's "CodeMirror 6 system guide"
(https://marijnhaverbeke.nl/blog/facets.html). The shape has held
up across a large open-source codebase under sustained extension
load; oneGrid bets the same design holds up under grid load.

### 2. `@onegrid/tokens` — 15 tests, 1.66 KB gz (+ 1 KB per theme)

**Architecture.** DTCG 2025.10 JSON bundles compiled at runtime to
CSS custom properties scoped to `[data-og-root]`. Theme via
`[data-og-theme]`; density via `[data-og-density]`. Sub-path
imports (`@onegrid/tokens/themes/light`, `…/density/compact`) so
adopters tree-shake the bundles they don't use.

**`flattenDtcg(bundle)`** walks the nested DTCG shape, resolves
`{group.subgroup.leaf}` aliases (one pass; cycles throw
`OG_TOKEN_CYCLE`), and returns a flat `Map<string, string|number>`.

**`compileTheme(bundle, opts)`** wraps the flattened declarations
in a CSS rule with optional `[data-og-theme="<name>"]` and
`[data-og-density="<name>"]` selectors.

**Catalogs** — 30 named color tokens, 15 density tokens. Every
built-in bundle is gate-tested to cover the full set so adopters
can validate their own bundles the same way.

**Built-ins:**
- themes: light, dark
- density: compact (24px), comfortable (32px), spacious (48px;
  matches Apple HIG 44pt / Material 48dp tap-target floors)

**`watchPrefersColorScheme(cb)`** — `matchMedia('(prefers-color-scheme:
dark)')` with cleanup. Safe to call in non-DOM environments
(returns a no-op cleanup).

**`forcedColorsBlock()`** — emits `@media (forced-colors: active)`
mapping our tokens to CSS Color Module Level 4 system color
keywords (`Canvas`, `CanvasText`, `Highlight`, `HighlightText`,
`GrayText`, `LinkText`). `forced-color-adjust: none` prevents the
OS from overriding our mapping.

**Plugin-kit bridge.** `registerTheme(bundle)` returns an Extension
the consumer attaches to their `PluginState`; the theme is then
discoverable via `themeRegistry.resolve(state, 'dark')`.

### 3. `defineGridOptions` nested config — 9 new tests, 56/56 core green

**Architecture.** `NestedGridOptions` is a parallel shape keyed by
domain (`data`, `columns`, `selection`, `editing`, `sorting`,
`filtering`, `grouping`, `pivot`, `rendering`, `scrolling`,
`a11y`, `i18n`, `touch`, `ssrm`, `formula`, `plugins`, `detail`,
`contextMenu`). The factory detects nested-vs-flat input and
normalizes to the existing flat shape that `Grid` consumes
internally. No invasive rewrite.

**Deprecation.** Flat fields emit one-time
`[OG_DEPRECATED_FLAT_OPT]` warnings keyed per field per session.
`@onegrid/migrate` will gain a `--from-flat-options` codemod.

**Validation.** Construct-time, with named error codes:
- `OG_INVALID_OPTION` — type/range
- `OG_OPT_REQUIRES` — `onFillHandle` without `enableFillHandle`
- `OG_OPT_CONFLICT` — reserved for future use
- `OG_OPT_UNKNOWN_NAMESPACE` — nested input has an unknown top-level key
- `OG_I18N_INVALID_LOCALE` — BCP 47 regex check

**Preset helpers** — `editingPreset`, `mobilePreset`,
`enterprisePreset`, `accessibilityPreset`. Each returns a partial
`NestedGridOptions` that spreads into the user's config.

**Reference.** ESLint flat config and Vite `defineConfig` shape —
typed factory + nested namespaces, no class hierarchy.

### 4. `@onegrid/headless` — 9 tests, 2.14 KB gz

**Architecture.** Thin wrapper around `Grid` with a Lit
`ReactiveController`-shaped lifecycle:

```
hostConnected()    // mount
requestUpdate()    // → rAF-coalesced flush
hostUpdate()       // pre-render hook
hostUpdated()      // post-render hook
hostDisconnected() // destroy
```

**rAF coalescing.** Multiple `requestUpdate(reason)` calls in one
frame produce one repaint with combined `reason` string. Cancels
the pending rAF on disconnect.

**Imperative surface** — `setSort`, `setFilter`, `setColumns`,
`setRowSource`, `scrollToRow`, `getSelection`, `getColumns`. Each
schedules a single coalesced update.

**Event channel** — `subscribe(event, listener)` returns an
unsubscribe function. Events: `mount`, `unmount`, `selectionChange`,
`sortChange`, `filterChange`, `columnsChange`, `scroll`, `frame`,
`invalidate`.

**SSR.** `renderAccessibilityShadowHTML()` returns a static
`role=grid` tree (header + 20 sample rows) with HTML-escaped
values. Client-side `hydrateFrom: existingShadowEl` adopts the
pre-rendered ARIA tree without unmounting.

**Reference.** Lit `ReactiveController`
(https://lit.dev/docs/composition/controllers/). The five-method
lifecycle vocabulary is small enough that Solid signals, Vue
composition functions, Svelte runes, and vanilla JS all bridge
to it in <50 lines.

### 5. Per-feature bundle budgeting — CI gate

**Architecture.** Each publishable package owns a
`bundle-budget.json`. `scripts/check-bundle-budget.mjs` walks every
budget file, gzips the named entry at level 9, compares against
the budget, and exits non-zero if any entry exceeds budget by
**>5%**.

**Escape hatch.** A commit message containing `[budget-bump: <pkg>]`
approves one bump for the named package. Justification belongs in
the PR description.

**Per-feature granularity.** Sub-path entries (themes, density,
future `@onegrid/core/features/*` entrypoints) each get their own
entry inside the package's `bundle-budget.json`. For features
gated behind a sub-path:

```
feature cost = bundle(core + feature) - bundle(core)
```

The budget covers the delta, not the absolute size.

**WebGPU + CPU fallbacks.** Both ship → budget the **sum**, not the
max. The fallback isn't "free" just because it's the non-preferred
branch.

**Current budgets** (gzip level 9):

| Package              | Budget   | Actual   |
| -------------------- | -------- | -------- |
| `@onegrid/protocol`  | 256 B    | 0.11 KB  |
| `@onegrid/plugin-kit`| 3 KB     | 2.09 KB  |
| `@onegrid/headless`  | 2.5 KB   | 2.14 KB  |
| `@onegrid/tokens`    | 2.5 KB   | 1.66 KB  |
| `@onegrid/touch`     | 4 KB     | 2.02 KB  |
| `@onegrid/intl`      | 4 KB     | 2.65 KB  |
| `@onegrid/react`     | 4 KB     | 3.36 KB  |
| `@onegrid/worker-plugins` | 2 KB | 1.04 KB  |

**Wired into CI** as `pnpm bundle:check` after `pnpm build`.

### 6. `@onegrid/intl` — 20 tests, 2.65 KB gz

**Architecture.** Three layers:

1. **`Intl.*` thin wrappers** — `formatNumber`, `formatDate`,
   `formatRelative`, `formatList`, `getCollator`. Each cached by
   `(locale, options)` because constructing `Intl.NumberFormat`
   is non-trivial and grids re-format the same column thousands of
   times per scroll.
2. **ICU MessageFormat (subset)** — substitution + plural + select
   implemented inline. Plural keyword set comes from
   `Intl.PluralRules`; `#` inside a plural arm substitutes the
   count via `formatNumber` (so "1,234 items" gets locale-correct
   group separators). No FormatJS dependency — keeps the bundle
   light; `formatTemplate` is exported as a hook point so consumers
   can wire full FormatJS themselves for nested formats / rich
   text.
3. **RTL helpers** — `getRtlAwareScrollLeft` abstracts the three
   engine-version conventions (positive-LTR, negative-RTL modern,
   reverse-RTL legacy Webkit) and returns the LTR-equivalent
   offset. `canonicalizeLocale` / `isValidLocale` are
   `Intl.Locale`-backed BCP 47 validators.

**Catalog surface.** `TRANSLATION_IDS` enumerates 75+ message ids
oneGrid emits (chevron labels, empty/loading/error states,
validation messages, context-menu items, column-tool panel,
row-group footers, 8 aggregation function names, 13 filter
operator names, status bar, floating-filter placeholders,
drag-drop indicators, pagination, tooltip help, detail panel,
12 month names + 7 weekday names + AM/PM, currency).

**Regional fallback.** `en-US` → `en` if the regional catalog
isn't loaded; matches FormatJS behavior.

**Locale-aware parsing.** `parseLocalizedNumber(input, locale)`
walks `Intl.NumberFormat.formatToParts(12345.6)` to learn the
group + decimal separators, strips groups, replaces the decimal,
strips currency symbols, and converts via `Number()`.

**Plugin-kit bridge.** `registerCatalog(catalog)` returns an
Extension routed to `i18nCatalogRegistry`.

### 7. `@onegrid/touch` — 15 tests, 2.02 KB gz

**Architecture.** Three modules in one file:

1. **`bindGestures(target, listener, opts)`** — Pointer Events
   Level 3-based recognizer. Tracks `Map<pointerId, PointerState>`
   for multi-pointer scenarios; uses `setPointerCapture` so a
   drag follows the pointer even past the target boundary.
   Gestures: `tap`, `doubleTap`, `longPress` (≥500 ms), `pan`,
   `panEnd`, `swipe`, `dragFromEdge`.
2. **`touchCss(selector)`** — emits the four-property CSS oneGrid
   expects:
   - `touch-action: manipulation` on `.og-tap` (no 350 ms delay)
   - `touch-action: none` on `.og-drag` (drag affordances)
   - `touch-action: pan-x pan-y` on `[data-og-grid-body]` (reserves
     pinch for the OS)
   - `overscroll-behavior: contain` on the body (no scroll chaining)
   - `@media (pointer: coarse)` block bumping row + chevron to
     `--og-size-touch-hit-zone` so 44pt/48dp is met
3. **`attachVirtualKeyboard(onInset)`** — prefers
   `navigator.virtualKeyboard.overlaysContent = true` + `geometrychange`
   listener (Chromium); falls back to `visualViewport.resize /
   scroll` for iOS Safari.

**`inputmodeForColumn(type)`** maps `ColumnType → HtmlInputMode`:
integers → `numeric`, floats → `decimal`, text → `text`, dates →
`numeric` (numeric soft-keypad is sensible when a picker drives
the actual value).

**Defaults.** `DEFAULT_LONG_PRESS_ACTION = 'context-menu'` — matches
Android + iOS platform conventions. Opt-in `'row-drag'` for
spreadsheet-style apps.

**Cleanup discipline.** `pointercancel` clears the long-press
timer and drops the pointer's state. The returned cleanup function
removes all four listeners and clears any in-flight timers — no
leaks on host unmount.

### 8. `@onegrid/worker-plugins` — 10 tests, 1.04 + 0.51 KB gz

**Architecture.** Second trust tier for user-supplied compute.

**Host side.** `new WorkerPluginHost({ worker })` wraps a `Worker`
(or `WorkerLike` shape for Node `worker_threads`). `invoke(fn,
args, transfer)` posts `{ kind: 'invoke', id, fn, args }`, returns
a promise. Per-call timeout (default 30 s). `.ready` resolves with
the list of registered handler names.

**Worker side.** `definePluginWorker({ handlers })` sets up the
dispatcher. Listens for `{ kind: 'invoke', id, fn, args }`,
awaits the handler, posts `{ kind: 'result', id, ok: true, value }`
or `{ kind: 'result', id, ok: false, error: { name, message,
stack? } }`. Throws are caught — the worker stays alive across
errors.

**Transferables.** `collectTransferables(args)` walks args for
ArrayBuffer-backed inputs (typed arrays, Arrow vectors with
`.buffer`) and returns them in the order they appear. For
hot-path code, pass `transfer` explicitly; for everything else,
let the helper find them.

**Iframe sandboxing intentionally NOT offered.** The overhead of
cross-origin iframe + postMessage is dominant on the hot path;
Workers already isolate the throw surface. If you need DOM-isolated
plugins specifically, wire an iframe yourself outside this package.

## Items 9–16 — research-pending (deferred)

These were scoped in the milestone but flagged for a second
research pass before implementation:

9. **Error boundaries + observability** — renderer/formatter/validator
   throws must not crash the grid. `onError(err, context)`, error-state
   cell rendering, React error-boundary integration, OpenTelemetry
   breadcrumbs. **Question:** does the grid retry, mark the cell
   `#ERR`, or unmount the row? Each has UX consequences.
10. **Schema evolution at runtime** — column added/removed mid-session.
    Selection-by-index vs by-id, sort/filter on a removed column,
    formula `#REF!` semantics, breaking-change detection for
    `setColumns`.
11. **Multi-tenancy / RLS / column permissions** — server-canonical
    permissions filter on `BlockRequest`; client-cosmetic UI
    hides/disables/read-only per column or row. Tricky boundary —
    client UI must NOT leak data the server is filtering.
12. **Backwards-compat / deprecation policy** — stable-vs-experimental
    tier within a major, warn-for-N-minor-versions before removal,
    `@deprecated` JSDoc + console.warn + ESLint rule.
13. **Adopter testing harness** — `@onegrid/test` recipes for
    Playwright / vitest browser mode. "row 5 column 3 contains 'X'",
    drive editing, wait for SSRM blocks, jsdom canvas limits.
14. **Print / advanced export** — PDF, screenshot, format-preserving
    Excel, `@media print`, header repetition per page.
15. **Validation system extensibility** — cross-cell / row-level /
    sheet-level validators on top of the per-cell validator. Adapton
    invalidation graph reuse. Topological pass cap.
16. **Runtime feature flags vs compile-time tree-shaking** — critical
    features always bundled; optional features opt-in via explicit
    imports. Conditional sub-path exports.

**Cadence.** Each will land as a `v0.0.9.x` patch as the research
finishes — same critical-path discipline, but one item at a time
rather than batched into the 8-item flush above.

## What this milestone changes for the codebase

Before v0.0.9, custom themes / locales / aggregators / filter
operators each lived as either hardcoded core constants or
ad-hoc registries (some via `Map`, some via array spreads). After
v0.0.9, **every customization surface goes through one framework
(`@onegrid/plugin-kit`)**, themed bundles ship as DTCG JSON,
config has one canonical nested shape, framework adapters can
delegate lifecycle to `@onegrid/headless`, and CI enforces that
adding a feature has a measurable bundle cost.

The total bundle floor for a minimal React app with theme + intl
+ touch is now **~46 KB gz** (core 25.98 + react 3.36 + tokens
1.66 + intl 2.65 + touch 2.02 + plugin-kit 2.09 + headless 2.14 +
data 6.90 + protocol 0.11). Without intl/touch (desktop-only,
single-locale), it's ~41 KB. The 8.8 KB v0.0.9 brings is the
price of being framework-, theme-, and locale-agnostic instead
of hardcoding any of those.
